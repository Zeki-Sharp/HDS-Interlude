## Architecture and setup

AstrBot authenticates the model broker with its official management API key. `host.cjs` authenticates all loopback requests using a separate bearer token; `worker.cjs` runs the Koishi service with SQLite. Only the exact configured QQ private account/owner pair is accepted. Utility commands stay in AstrBot's tool pipeline, while normal dialogue is generated by HDSI. A QQ message ID is required before marking a reply sent; ambiguous attempts stay `unknown` across restarts.

Use Node 20.18 or newer, AstrBot 4.28.2's plugin APIs, and the dependencies in this directory. The validated environment uses Node 24 and Python 3.12. Install with `npm ci`, set `NODE_PATH` to this directory's `node_modules`, then run `node build.cjs` to rebuild the root `lib/index.js`. The standalone build avoids requiring the upstream Koishi monorepo's parent tsconfig. It builds runtime JS; the two added public declarations are maintained alongside their source in `lib/service.d.ts`.

The pinned upstream commit's source already contains fixes absent from its checked-in bundle (Agency candidate synthesis, withdrawn-intent annotations, web-observation error isolation). Rebuilding includes those source fixes as well as this fork's changes. The corresponding upstream Issue 10/14 and Agency regression suites are included in validation; the original bundle remains available at the upstream commit for rollback.

Provide a private JSON file through `HDSI_CONFIG`; it contains `upstream` (checkout path), `dataDir`, `port` (4192 recommended), `token`, `owner`, `instance`, `mode`, `proactive`, `dailyCalls`, `dailyOutputTokens`, `contactPolicy` and the normal upstream `hdsi` configuration. Set `ASTRBOT_ADMIN_API_KEY` in the host process environment. The broker is at `127.0.0.1:6185`; the HDSI model provider endpoint must point back to this host's `/v1/chat/completions` and use its token. Do not use port 4190: Node Fetch rejects that port.

Start `node host.cjs` with these private settings. Upload the `astrbot_plugin_hdsi_bridge` directory through AstrBot's official API; configure the same host/token and exact `scope`/`persona_id`. Keep `enabled=false` until health, bindings and isolated tests pass. Changing a persona alone does not update the conversation override, memory family, approved image bindings or formatter targets.

## Contact and evolution

`contactPolicy` accepts `startHour`, `endHour`, `dailyCap`, `minIntervalMinutes` (Asia/Shanghai; end exclusive; overnight windows supported). Omitted fields preserve the earlier defaults 09–22 / 2 / 180. Align upstream Agency's cap and interval with this final delivery guard. A new inbound reactive reply bypasses proactive limits; proactive attempts consume capacity even if delivery fails. Upstream's rolling contact window and platform constraints may further reduce sending. The model has a separate 12-background-call daily budget, plus configurable total call/output limits.

`hdsi.memory.autoApplyPaths` optionally restricts automatic development paths, e.g. `character.preferences`, `character.coping`, `perspective.interpretation`, `relationship.trust`, `relationship.boundaries`. Empty preserves upstream behavior. Out-of-list candidates remain proposals. Existing turn/day/confidence/cooldown and private/global evidence boundaries still apply. `allowMajorStateChanges=false` blocks major automatic changes, including a major candidate later re-described as minor. Persona core text remains unchanged.

In the configured private conversation: `/幕间 状态` or `/幕间 演化` shows recent sourced proposals and emotion; `/幕间 撤销 123` clears a recent applied proposal and rebuilds live projection while preserving evidence. Already compacted changes cannot be individually revoked here; use the upstream target-level overlay clearing workflow after inspecting snapshots. This is audit-preserving reversal, not physical erasure. Automatic future new evidence can generate new proposals.

The authenticated host also provides `/evolution`, `/revoke`, `/setting`, `/state`, `/advance`, `/background`, `/health` and `/stop`. Setting updates use the HDSI service API; never write a running database directly. Back up the runtime directory only after a clean stop.

## Music

Plain-text shares record user-supplied titles/links separately from retrieved metadata. NetEase numeric song links can resolve title and artists; QQ links and title-only shares are retained without pretending metadata was fetched. Title/link conflicts are flagged. Lookup only accesses a fixed official metadata URL with numeric IDs, never arbitrary user destinations. Music cards and attachment/audio understanding are not implemented. `audio_analyzed=false` always; a share, metadata response or playback receipt is not evidence of hearing the song. Sharing can inform fictional plans and interests.

## Validation and updates

Run `node --test policy.test.cjs`, Python `astrbot_plugin_hdsi_bridge/test_music_share.py`, and from the repository root `tsx --tsconfig integrations/astrbot/tsconfig.json --test test/astrbot-evolution-policy.test.ts test/m7-m8-continuity.test.ts test/alter-concurrency.test.ts test/proactive-modes.test.ts test/world-seeder.test.ts`. Isolated model and transport tests are deployment-specific; synthetic receipts are not QQ acceptance.

Keep `origin` pointing to your fork and `upstream` to `ISEKAI-MomoiCore/HDS-Interlude`. Fetch upstream without touching production. On a new `codex/...` branch from the last tested release, merge a chosen upstream commit, resolve conflicts in source, rebuild, and rerun isolated checks. Conflicts are expected if upstream changes the same service/schema/transport area; a fork does not prevent upstream updates. Never auto-pull a running deployment or overwrite customized code with upstream's prebuilt bundle.

For rollback keep the previous code commit, host/plugin configuration and a stopped backup. Restore previous code/config through the deployment tools and official APIs; retaining the newer database preserves new conversations but also retains their development history. Restoring an entire older database snapshot loses post-snapshot events and therefore requires an explicit choice. Rehearse with an isolated copy first.
